# Desktop UI redesign

User approved the proposed Run / Calibration / Buffs / Settings redesign and explicitly requested full implementation, icons, meaningful labels/placeholders/tooltips, preservation of all functions, and interaction plus native visual verification.

The player prepares a profile occasionally, then needs clear runtime state and actionable explanations. The shared runtime/profile/editor remain authoritative. One header owns profile selection, Save / Save & Start, Pause F8, and theme. Four persistent navigation destinations replace the always-visible calibration canvas. Run shows current state, next action, honest statistics, buff countdowns and readiness. Calibration retains all frozen/live editing, masks, independent crops, zoom/pan/history and shortcuts, with an ordered clickable checklist. Buffs uses a compact eight-skill list and selected detail; image selection temporarily opens the same calibration canvas with an explicit return action. Settings groups existing fields with units and explanations. A width-adaptive layout keeps all controls reachable at 800x560 and supports both themes.

Graphite / off-white surfaces, blue action/selection, muted jade healthy status, amber intervention and red errors express target search, panel confirmation, buffs, mount state and input safety. Icons are a small shared set drawn with egui paths, never Unicode icon glyphs; every action retains a label or accessible name plus tooltip. Disabled Start gives the actual next step; fixed-crop readiness uses loaded pixels even for migrated profiles without a crop region. Current mount is explicitly user-declared, separate from desired fight-mounted behavior. No inferred kill counts or invented buff recognition status.

All existing fields and commands remain available, including profile rename/new/switch/save, mount declaration, eight skills/reorder/remove/units/modes/timers/active-inactive crops/reuse, numeric ranges, platform diagnostics, Reset statistics, snapshots and editor gestures. No new OS gameplay backend, production cutover, push or release is authorized by this UI request.

Verification: meaningful pointer/navigation/editing/state regressions, all workspace tests, fmt, strict Clippy, Windows/Linux builds, real native screenshots of each destination in both themes and small/large widths, plus representative tooltip/empty/error/editor states. Native gameplay and macOS acceptance remain the earlier migration gates. A later independent user review can use the scenario checklist in the UI verification report.
